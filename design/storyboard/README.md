# 恋爱吗 · Android 助手键盘 Demo 分镜

三张连续分镜板，共九个状态。展示同一位虚构联系人「小雨」的完整使用过程。

1. 导入聊天截图 → 确认双方与文字 → 上下文就绪。
2. 微信收到消息 → 复制并加入上下文 → 生成回复建议。
3. 查看关系依据 → 调整表达并填入 → 用户在微信发送。

产品形态：Android 配套 App + 原生辅助输入法。配套 App 负责历史截图导入，键盘负责上下文更新、关系信号和回复建议。用户手动选择联系人、导入消息并发送。

所有聊天、人物和分数均为虚构演示数据。互动温度不是恋爱成功率。画面是概念 mockup，并非已经运行的产品截图。

图像使用内置 ImageGen 工具生成；完整生成提示词随图片保存。

## 现场讲解顺序

01–03：先在配套 App 中导入连续聊天截图，核对识别结果及双方身份。完成后由用户手动返回微信，切换到预先安装、启用的恋爱吗键盘。

04–06：收到新消息后，长按复制。键盘展示剪贴板预览，用户确认将其作为对方消息加入当前联系人的上下文，然后生成三种回复方向。输入框此时仍为空。

07–08：查看互动温度与聊天依据；示例分数 72/100 是产品概念数据，不是实际模型输出，也不是恋爱概率。用户可以选择回复方向并调整措辞。

09：用户点击「填入微信」后，建议成为微信输入框中的草稿。用户可切回常用键盘继续编辑，再手动点击微信的发送按钮。分镜停在发送前，不表现自动代发。

## 能力边界与开发对应

- 键盘不自动读取微信历史，不自动知道当前联系人；联系人需由用户选定。
- 原生键盘界面负责建议、判断与写入输入框；历史截图由配套 App 导入。
- 识图与文本生成交由相应模型处理；Jev 负责明确标准下的结构化判断与评分。
- 「帮我回」优先呈现即时任务；「我们怎样」展示依据与不确定性。
- 微信界面是用于说明交互关系的概念示意，真实实现需在目标 Android 微信版本上验证。
